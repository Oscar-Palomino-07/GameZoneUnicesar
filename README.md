# GameZone Unicesar

Console-based inventory and sales management system for GameZone Unicesar, a video game store in the university district of Valledupar. Developed in Java with Maven and organized in four layers: model, persistence, service and user interface.

## Features

- Register video games and consoles.
- List all products available in the inventory.
- Register customers and list the registered customers and sellers.
- Register a sale with automatic stock discount and total calculation, accepting video games, consoles and accessories (accessory stock is discounted automatically too).
- Consult the complete sales history, the purchases of a specific customer and the sales attended by a specific seller.
- Register percentage, category and bulk purchase promotions with a validity period. When a sale is registered, the active promotion that grants the largest discount is applied automatically (only one per sale) and the receipt shows the subtotal, the discount with the promotion name, the cost of the extended warranties and the final total.
- Consult the detail of a specific sale, including its receipt, and list all the registered promotions or only the ones that are active today.
- Register accessories (controllers, cables and memories) with console compatibility.
- List all accessories, filter them by type and consult the accessories compatible with a specific console.
- Every console included in a sale automatically receives a 6-month basic warranty at no cost. When registering the sale, the seller can also add a 12-month extended warranty to each console; its cost (10% of the console price) is added to the total of the sale.
- Consult the warranty of a product within a sale, list all the warranties, list the warranties that are active today and list the warranties that expire within a given number of days.
- All information is stored in JSON files and loaded automatically at startup.

## Requirements

- Java 17 or later
- Maven 3.x

## Build

```bash
mvn clean package
```

## Run

```bash
java -jar target/gamezone-unicesar.jar
```

On the first run the application is ready to use: it loads the preloaded sellers from `data/sellers.json` and creates the remaining data files as they are needed.

### Main menu

- **1. Products** — register a video game, register a console, list all products
- **2. People** — register a customer, list customers, list sellers
- **3. Sales** — register a sale (the menu asks whether to add the extended warranty to each console and prints the receipt), view all sales, view sales by customer, view sales by seller, view the detail (receipt) of a sale
- **4. Returns** — register a return, view all returns, view returns by customer, view returns by sale
- **5. Accessories** — register a controller/cable/memory, list all accessories, filter by type, consult compatibility with a console
- **6. Reports** — monthly balance (sales - returns)
- **7. Gestión de garantías** — consult the warranty of a product in a sale, list all warranties, list active warranties, list warranties expiring soon (this submenu is in Spanish, as required by the exam statement)
- **8. Gestión de promociones** — register a percentage, category or bulk purchase promotion, list all promotions, list the promotions that are active today (Spanish submenu)
- **0. Exit**

## Project structure

```
com.gamezone
├── model         domain classes (Person, Customer, Seller, Product, VideoGame, Console, Accessory, Controller, Cable, Memory, Sale, Warranty, BasicWarranty, ExtendedWarranty, Promotion, PercentageDiscount, CategoryDiscount, BulkPurchaseDiscount)
├── persistence   file-based repositories (JSON with Gson)
├── service       business rules (PersonService, ProductService, AccessoryService, WarrantyService, PromotionService, SaleService)
├── ui            console menu
└── Main.java     entry point; wires repositories, services and the menu
```

The layered architecture restricts the dependencies between layers: the user interface only talks to the services, the services validate the business rules and persist changes through the repositories, the repositories read and write the JSON files, and the model classes contain no file or user interface logic.

## Data files

The application persists all information under `data/`:

- `sellers.json` — preloaded sellers (three on the first run)
- `customers.json` — registered customers
- `videogames.json` and `consoles.json` — product inventory
- `accessories.json` — accessory inventory (controllers, cables and memories)
- `sales.json` — registered sales (including the applied promotion, its discount and the extra cost of the extended warranties)
- `promotions.json` — promotions (three preloaded: one percentage, one category and one bulk purchase promotion)
- `warranties.json` — warranties generated by console sales, one record per warranty with a `BASIC`/`EXTENDED` type discriminator (they only store the sale and product identifiers; the end date is calculated from the start date and the warranty type)
